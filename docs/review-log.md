# Итеративное ревью

Цель: читаемый, идиоматичный и проверенный код локальной игры. Каждый этап:
наблюдаемая проблема → исправление → проверка итогового diff → отдельный коммит.
Смена стека сама по себе не является улучшением.

## Исходное состояние

Коммит `9dd49cd`: `npm run verify` проходит, 14 тестов. Это проверяет базовые
правила, но не доказывает корректность браузерных взаимодействий, всех форматов
сохранения или обработки ошибок.

## 1. Читаемая разметка

- Ревью: автоматическое форматирование сохраняло слипшиеся Svelte-блоки и
  несколько соседних элементов на одной строке.
- Исправление: явно разделены управляющие блоки; для разметки установлено
  `htmlWhitespaceSensitivity: ignore`, совместимое с flex/grid интерфейсом.
- Проверка: итоговая разметка просмотрена; `npm run verify` проходит (14 тестов,
  ноль ошибок и предупреждений Svelte, production-сборка).

## 2. Границы данных

- Ревью воспроизведено: 12 из 16 новых сценариев падают на исходном коде.
  Дубли в колоде, неверная фаза/таймер и несовпадающие имена принимались;
  `null`/неполная legacy-запись приводили к случайным TypeError; повреждённая
  партия блокировала чтение исправных настроек.
- Исправление: JSON принимается как `unknown`; сначала проверяется envelope и
  структура legacy-массивов, затем доменные инварианты. Настройки партии
  проверяются одним валидатором в движке и инструментах агента. Черновые
  настройки допускают незавершённый ввод. Чтение настроек отделено от партии.
- Словари проверяются до начала игры: строковые непустые слова допустимой длины,
  все четыре набора. Убраны assertions, подменявшие проверку типов JSON.
- Проверка: регрессии воспроизводились до исправления и проходят после;
  исходные сценарии миграции/полубаллов сохранены. `npm run verify` проходит.

## 3. Контроллер, lifecycle и запись

- Ревью: фоновый переход очищал чужую блокировку диалога; отложенный keyup мог
  отпустить новое нажатие; callbacks не отменялись при teardown. Ошибка записи
  приводила к повтору каждые 100 мс; неизменная партия переписывалась в меню.
  Получение `localStorage` происходило вне recovery, а обновление перезагружало
  страницу даже при неудачном сохранении.
- Исправление: lifecycle физических событий вынесен отдельно с симметричным
  cleanup; release отложен до native activation, старые callbacks отменяются.
  Фон сбрасывает только физические holds. Контроллер принимает часы/хранилище/
  загрузчик для воспроизводимых проверок, сохраняет изменившиеся данные,
  ограничивает периодические повторы и отдельно фиксирует переход к последнему
  слову. Обновление PWA зависит от успешного checkpoint.
- Проверка: тесты реального контроллера проверяют фон + открытый modal, storage
  getter SecurityError, QuotaExceeded, отсутствие лишних записей и повторов,
  retry загрузки и остановку после detach. Тест событий проверяет порядок keyup
  и повторного keydown, независимость modal и снятие listeners/callbacks.
  `npm run verify` проходит; браузерный проход остаётся отдельной проверкой.

## 4. Жесты и доступность

- Ревью: отмена жеста не учитывала потерю pointer capture, правую кнопку мыши
  и отсутствие compatibility click; диалог не имел accessible name и
  намеренного начального фокуса. Закрытие ошибки загрузки убирало retry.
- Исправление: жест имеет одну origin и идентификатор подавляемого click;
  cancel/lostcapture не начисляет очков, новый tap и клавиатура не блокируются.
  На карточке разрешён pinch zoom. Диалоги именуются через `aria-labelledby`,
  фокусируются на заголовке, отмене подтверждения или первом угадывающем.
  Ошибка загрузки остаётся доступной для retry; готовность офлайн показана в
  правилах, сбой регистрации worker виден в интерфейсе.
- Проверка: четыре сценария жестов (оба направления, cancellation, чужой
  pointer, короткий/диагональный жест, правая кнопка, click suppression и
  клавиатура); `npm run verify` проходит — 46 тестов. Реальные pointer/focus/SW
  взаимодействия будут проверены итоговым браузерным проходом.

## 5. Типы, движок и компоненты

- Ревью: проверка `noUncheckedIndexedAccess` выявила 21 недоказанное обращение
  к массивам. Правила начисления читались как цепочка вложенных ternary;
  форматирование счёта/журнала жило в движке/разметке; App содержал целиком
  экран передачи телефона и правила, а контроллер назывался `c`.
- Исправление: включены проверки индексов, возвратов, switch и неиспользуемого
  кода. Доступ к игрокам и непустой рейтинг имеют явные контракты; убраны
  assertions слова/фазы, switch проверяет исчерпываемость. Начисление очков
  читается отдельными ветками и сохраняет ссылки на неизменённых игроков.
  Нулевой тик не создаёт новое состояние. Представление вынесено в небольшой
  модуль; Ready/Rules стали компонентами; используются ясные имена/derived
  значения. CSS сгруппирован, удалён мёртвый selector и временный хвост правки.
- Проверка: `npm run verify` — 50 тестов, ноль диагностик. Добавлена полная
  детерминированная партия через все фазы с сериализацией каждого состояния,
  замороженными входами reducer и проверкой отсутствия повторов; ошибочный
  источник shuffle отвергается до повреждения колоды.

## 6. Постоянные проверки качества

- Ревью: форматтер и компилятор не проверяли небезопасный `any`, обработку
  Promise, Svelte-специфичные ошибки и идентичность элементов each.
- Исправление: официальный `eslint-plugin-svelte`, typed recommended
  `typescript-eslint`, flat config и совместимость с Prettier. Runes-модули
  парсятся как TypeScript по конфигурации Svelte. Код имеет явные блоки условий,
  списки — ключи (редактируемые имена хранятся по позиции, не по меняющемуся
  тексту). Исправлены contextual types mocks. Зависимости зафиксированы lockfile.
  `npm run verify` и CI теперь включают lint с нулём предупреждений.
- Проверка: typed lint проходит без blanket suppression; format, типы,
  50 тестов и production-сборка проходят. npm audit при установке: 0 уязвимостей.

## 7. Браузерное контрсвидетельство: фокус

- Production-проверка обнаружила выход фокуса в BODY/браузер при Shift+Tab на
  первой кнопке native dialog. Это не покрывалось доменными тестами.
- Исправление: диалог явно замыкает Tab/Shift+Tab на своих доступных действиях;
  остальные клавиши и Escape остаются нативными.
- Повторная проверка на новой production-сборке: Shift+Tab с «Закрыть» переходит
  к последней ссылке, Tab с ссылки — к «Закрыть»; оба фокуса внутри dialog.
  Escape возвращает фокус к «Правила». Обновление SW сохранило текущую партию
  и слово; применённый asset проверен по DOM. `npm run verify` проходит.

## 8. Повторное ревью настройки и браузерных ошибок

- Браузерный проход выявил дублирование автоматически добавленного имени после
  удаления/переименования игрока. Повторное ревью обнаружило изменение настроек
  до успешного создания новой партии и общий массив настроек с игровой моделью.
- Исправление: добавление/удаление игрока принадлежит контроллеру и соблюдает
  общие ограничения; автоматически выбранное имя свободно. Новая партия
  сначала полностью создаётся, затем применяется; редактируемые массивы
  отделены от её конфигурации. UI, сохранение и WebMCP используют общие пределы.
  Ошибки установки/обновления PWA имеют recovery в интерфейсе.
- Проверка: три регрессии; `npm run verify` проходит — 53 теста, ноль диагностик
  Svelte/TypeScript и предупреждений ESLint, корректный формат и production build.
  Development-браузер не сообщает ошибок/warnings, включая 12 игроков и имена
  длиной 24 символа на экране 320 × 568.

## 10. Совместимость очистки WebMCP

- Во время нового браузерного прохода HMR обнаружил `unregisterTool is not a
function`: используемый браузер предоставляет регистрацию инструментов без
  симметричного метода очистки. Это прерывало teardown Svelte.
- Исправление: очистка учитывает отсутствие опционального browser API.
- Проверка: регрессии для обеих реализаций — с методом unregister и без него.

## 11. Phone-first: высота экрана и однократное нажатие

- Обратная связь: на телефоне требовалось повторное нажатие паузы/игрока после
  свайпа, появлялись визуальные артефакты; ход не помещался вертикально, включая
  складной экран 3:4. Ревью выявило hover без проверки устройства, сдвиг кнопки
  при нажатии и синхронное открытие native dialog внутри pointerup.
- Исправление: hover/переходы кнопок доступны только для fine pointer с hover,
  сдвиг удалён. Диалог открывается после завершения pointer activation;
  фокус не прокручивает страницу, callback отменяется при unmount. Это устраняет
  риск конфликта pointer capture/последующего click; точная причина на физическом
  телефоне пользователя не воспроизведена.
- Layout: ход занимает `100dvh` на телефонах, сенсорных устройствах и экранах
  шириной до 1024 px. Счёт вынесен в доступный диалог; лишнее дублирование меню
  и нижнее сообщение не занимают игровую высоту (status сохранён для screen reader).
  Основные действия имеют высоту не менее 44 px. Карточка занимает остаток высоты.
  Прямой выбор игроков сохранён, пока группа помещается; для большой группы или
  низкого экрана используется picker. Сетка picker имеет 2 колонки в портрете,
  3 в низком landscape, без повторения «+1» в каждой мобильной кнопке.
- Браузер: 3, 7 и 12 игроков, длинные имена; пауза/продолжение по одному нажатию,
  свайп вверх → один выбор игрока → ровно +1/+0,5. Основной ход не имеет
  document overflow; кнопки находятся внутри viewport на 320 × 480, 320 × 568,
  360 × 640, 390 × 844, 568 × 320, 844 × 390, 720 × 960, 768 × 1024,
  900 × 1200 и 1024 × 768. Desktop 1280 × 800 также проверен.
  Picker на 12 игроков с длинными именами: 0 px внутренней прокрутки на
  320 × 480 (408 px высоты) и 568 × 320 (288 px). Передача телефона на
  320 × 480 также помещается без прокрутки.
- Основания для проверки touch: [WebKit про sticky hover](https://bugs.webkit.org/show_bug.cgi?id=245571)
  и [W3C Pointer Events](https://www.w3.org/TR/pointerevents/latest/).
  Это браузерные проверки геометрии и активации мышью; они не подменяют проверку
  реального touchscreen, увеличенного системного шрифта или Fold пользователя.
- Итог: `npm run verify` — 55 тестов, ноль ошибок/предупреждений. Отдельная
  production-партия на 5 игроков в 320 × 480: 0 px прокрутки, кнопки не ниже
  44 px; свайп и один выбор дают +1/+0,5, три цикла пауза/продолжение выполнены
  по одному нажатию на действие. Диалог счёта приостанавливает время; консоль
  production без ошибок/warnings. Сохранены скриншоты 320 × 480 и 720 × 960.

## 12. Повторный remount инструментов агента

- Дополнительное контрсвидетельство после этапа 10: без unregister повторный
  mount приводил к `Duplicate tool name`, а callback мог удерживать прежний
  контроллер. Ошибка асинхронной регистрации не обрабатывалась.
- Исправление: регистрация выполняется один раз на browser context; callbacks
  перенаправляются к текущему контроллеру. Cleanup прежнего владельца не снимает
  новую партию. Асинхронная ошибка регистрации обработана; при изменении самих
  descriptor/handler-модулей Vite делает полную перезагрузку через documented
  [HMR API](https://vite.dev/guide/api-hmr.html).
- Проверка: регрессия remount → чтение новой партии → cleanup старого владельца;
  в реальном браузере выполнен HMR App с временным DOM-маркером, агентский resume
  изменил текущий интерфейс, счёт сохранился, ошибок/warnings нет. Временный
  маркер удалён. Полный `verify` проходит — 56 тестов.

## 13. Одно касание в установленной Android PWA

- Контрсвидетельство пользователя: после ограничения hover и изменения открытия
  диалога имена и почти все кнопки по-прежнему требовали два касания в установленной
  PWA. Поэтому прежний проход мышью недостаточен для проверки этой ошибки.
- Исправление: общий native `ActionButton` активирует короткое primary touch/pen
  на `pointerup`. Мышь, клавиатура и accessibility используют обычный click.
  Перед действием устанавливается общий capture-guard: последующий compatibility
  click подавляется даже после удаления диалога и смены элемента под пальцем.
  Новый pointerdown сбрасывает guard; отсутствие click у предыдущего касания
  не съедает следующий tap. Системная прокрутка, движение более 12 px,
  pointercancel и отпускание вне кнопки не активируют действие.
- Применено ко всем кнопкам меню, настроек, игры, результатов, диалогов и обновления
  PWA. Карточка слова сохраняет вертикальные свайпы, а короткий touch открывает
  выбор угадавшего на pointerup с тем же guard.
- Проверки: 67 автоматических тестов и полный `npm run verify`. В настоящем
  браузере временный Svelte harness с синтетическими touch PointerEvents проверил
  10 сценариев: tap с/без click, следующий tap с тем же id, движение и отмену,
  pause/resume, клавиатурную активацию, закрытие dialog с click на открывшуюся
  кнопку и следующий tap после dialog. Все PASS; warnings/errors отсутствуют.
  Временные файлы удалены. Реальный UI на 320 × 480: один выбор после свайпа
  даёт +1/+0,5; pause/resume, открытие и закрытие счёта работают одним нажатием
  мыши. Переполнение документа 0 px. Физическая Android PWA пользователя пока
  не проверена.

## 14. Офлайн-подсказки, история и исправление результатов

- Режим подсказок включается в настройках новой партии. Использование определения
  записывается для текущего слова и в историю; угадавшему +1, объясняющему +0.
  Повторное открытие, сохранение, перезапуск и отмена ответа сохраняют штраф к бонусу.
  Пропуск по-прежнему даёт −1. При отсутствии определения подсказка недоступна и
  бонус не снимается. Открытая подсказка и раскрытая история удерживают часы.
- Встроены 17 263 определения для 17 554 игровых слов: 98,3% покрытия, 5,6 MB
  несжатого JSON. Источник: [русский Викисловарь / Kaikki](https://kaikki.org/ruwiktionary/).
  Локальный asset загружается один раз при старте и входит в precache; показ
  слова не вызывает сетевой запрос. Исходный большой dump не публикуется.
  Script, SHA-256 источника, отсутствующие слова, статистика покрытия и
  атрибуция CC BY-SA 4.0 сохранены в репозитории.
- В результатах хода и последнего хода завершённой игры можно переназначить
  угадавшего либо отметить пропуск. Старые начисления снимаются и новые
  применяются атомарно; бонус подсказки сохраняется. Если исправление снимает
  победу по целевым очкам, результат возвращается к завершённому ходу и
  следующему объясняющему, без пропуска очереди. Итоговая партия теперь
  сохраняется для последующей проверки результатов.
- История текущего хода раскрывается через native details/summary. На компактном
  экране она временно занимает область карточки; внутренний список прокручивается,
  основные кнопки остаются на месте. Проверены 320 × 480, 568 × 320,
  844 × 390 и 720 × 960: нулевая прокрутка документа, нет наложений.
  Отдельно проверены пять игроков с именами по 24 символа; на низком телефоне
  они доступны через окно выбора, на Fold — непосредственно на экране.
- Native touch activation вынесена в общий Svelte attachment для кнопок и
  summary, с прежней защитой compatibility click. Семь сценариев в настоящем
  браузере с синтетическими touch PointerEvents: одиночный tap+click, следующий
  tap без click у предыдущего, отмена, раскрытие/сворачивание/отмена истории,
  keyboard click — PASS. Временный probe удалён; физический Fold не проверялся.
- Автоматически проверены бонус с подсказкой/без, undo, последнее слово,
  восстановление сохранения, отсутствующее определение, переназначение/пропуск
  в обе стороны, отмена победы и исторический нулевой бонус без подсказки.
  `npm run verify`: 77 тестов, ноль ошибок/warnings, production precache содержит
  определения. В браузере определение «вдохновитель» даёт 0/+1; переназначение
  Борис → Вера переносит только +1 и сохраняется после reload.
- Production-проверка офлайн: дождались «Офлайн-режим готов», открыли «патент»,

## Итоговый браузерный проход

- Production: одиночное нажатие на игрока даёт +1 ему и +0,5 объясняющему;
  свайп вниз даёт −1 объясняющему, включая отрицательный счёт. Свайп вверх
  открывает выбор игрока; compatibility click не вызывает повторное действие.
  Обычный tap после свайпа остаётся рабочим.
- Открытый выбор игрока сохраняет точное время, ручная пауза скрывает слово.
  Две отмены возвращают исходное слово, счёт и размер оставшейся колоды.
  После естественного истечения таймера текущее слово доигрывается без времени;
  результат хода и передача следующему объясняющему корректны.
- Проверены 320 × 568, 390 × 844, 768 × 1024, 1280 × 800 и 844 × 390:
  нет горизонтального переполнения и обрезанных кнопок; время на паузе неизменно.
  Дополнительно проверены 12 игроков с длинным именем в development-сборке.
- Обновление service worker применено кнопкой на production-сборке;
  новая версия подтверждена по загруженному JS asset. Партия сохранена.
  После остановки preview-сервера страница перезагружена из кэша, сохранённая
  партия продолжена с прежним словом «античность», игроками, счётом и временем.
  Production-консоль не содержит ошибок или предупреждений.
- Установка и жесты на физических iOS/Android-устройствах не проверялись.
  Браузерный проход дополняет автоматические проверки; он не доказывает
  отсутствие всех возможных ошибок.

Практики и первоисточники собраны в [frontend-practices.md](frontend-practices.md).

## Ничья за слово и подсказка без общего режима

- В выборе угадавшего добавлена «Ничья»: выбор двух имён, затем явное
  подтверждение. Обычный ответ сохраняет одно нажатие. Угадавшим по +0,5,
  объясняющему один бонус +0,5 (или 0 после подсказки).
- Один общий компонент выбора используется в раунде и исправлении результатов.
  Ничья — одна запись истории; отмена, пересчёт и восстановление сохранений
  учитывают обоих игроков. Прежние записи с одним угадавшим продолжают работать.
- Подсказку можно открыть на любом текущем слове. Общий переключатель убран;
  старые партии с выключенным режимом тоже допускают подсказку. Бонус снимается
  только с прочитанного слова и возвращается на следующем.
- В реальном браузере на 320×480 выбор ничьей целиком помещается в окне,
  оба имени выбираются с первого нажатия. Проверены ничья без подсказки,
  одиночный ответ с подсказкой, обычный бонус следующего слова и исправление
  ничья → один игрок и ответ с подсказкой → ничья. Очки и история совпадают.
- После перезагрузки история и оба участника ничьей восстановлены. На формате
  720×960 окно исправления полностью помещается. Итоговый `npm run verify`:
  90 тестов, lint и проверка Svelte без ошибок, production/PWA-сборка готова.

## Ничья для любого числа угадавших

- Выбор ничьей допускает всех угадывающих, без ограничения двумя. Перед
  подтверждением видны число выбранных игроков и доля каждого. Один балл
  делится поровну с округлением вниз до сотых: троим +0,33, шестерым +0,16.
  Остаток не перераспределяется; бонус объясняющего начисляется один раз.
- Счёт хранится целыми сотыми. Формат сохранения 3 переносит старые полубаллы
  и пары угадавших из 2.x; миграция 1.x также сохранена. Текущая запись имеет
  приоритет перед прежней, поэтому повторная загрузка не масштабирует очки.
- Автоматически проверены все группы от 2 до 11 угадавших, отмена, точное
  сложение, исправление состава, подсказки, граница победы и старые сохранения.
- В браузере на 320×480: выбор шести игроков помещается без прокрутки страницы,
  при выборе троих показано +0,33, шестерых +0,16. Подтверждение начисляет
  точную долю; исправление трое → шестеро пересчитывает очки. После перезагрузки
  все шесть получателей и их 0,16 восстанавливаются.
- `npm run verify`: 112 тестов, lint и Svelte без ошибок, PWA-сборка готова.
