# Итеративное ревью

Цель: читаемый, идиоматичный и проверенный код локальной игры. Каждый этап:
наблюдаемая проблема → исправление → проверка итогового diff → отдельный коммит.
Смена стека сама по себе не является улучшением.

## Исходное состояние

Коммит `9dd49cd`: `npm run verify` проходит, 14 тестов. Это проверяет базовые
правила, но не доказывает корректность браузерных взаимодействий, всех форматов
сохранения или обработки ошибок.

## 1. Читаемая разметка

- Ревью: автоматическое форматирование сохраняло слипшиеся Svelte-блоки и
  несколько соседних элементов на одной строке.
- Исправление: явно разделены управляющие блоки; для разметки установлено
  `htmlWhitespaceSensitivity: ignore`, совместимое с flex/grid интерфейсом.
- Проверка: итоговая разметка просмотрена; `npm run verify` проходит (14 тестов,
  ноль ошибок и предупреждений Svelte, production-сборка).

## 2. Границы данных

- Ревью воспроизведено: 12 из 16 новых сценариев падают на исходном коде.
  Дубли в колоде, неверная фаза/таймер и несовпадающие имена принимались;
  `null`/неполная legacy-запись приводили к случайным TypeError; повреждённая
  партия блокировала чтение исправных настроек.
- Исправление: JSON принимается как `unknown`; сначала проверяется envelope и
  структура legacy-массивов, затем доменные инварианты. Настройки партии
  проверяются одним валидатором в движке и инструментах агента. Черновые
  настройки допускают незавершённый ввод. Чтение настроек отделено от партии.
- Словари проверяются до начала игры: строковые непустые слова допустимой длины,
  все четыре набора. Убраны assertions, подменявшие проверку типов JSON.
- Проверка: регрессии воспроизводились до исправления и проходят после;
  исходные сценарии миграции/полубаллов сохранены. `npm run verify` проходит.

## 3. Контроллер, lifecycle и запись

- Ревью: фоновый переход очищал чужую блокировку диалога; отложенный keyup мог
  отпустить новое нажатие; callbacks не отменялись при teardown. Ошибка записи
  приводила к повтору каждые 100 мс; неизменная партия переписывалась в меню.
  Получение `localStorage` происходило вне recovery, а обновление перезагружало
  страницу даже при неудачном сохранении.
- Исправление: lifecycle физических событий вынесен отдельно с симметричным
  cleanup; release отложен до native activation, старые callbacks отменяются.
  Фон сбрасывает только физические holds. Контроллер принимает часы/хранилище/
  загрузчик для воспроизводимых проверок, сохраняет изменившиеся данные,
  ограничивает периодические повторы и отдельно фиксирует переход к последнему
  слову. Обновление PWA зависит от успешного checkpoint.
- Проверка: тесты реального контроллера проверяют фон + открытый modal, storage
  getter SecurityError, QuotaExceeded, отсутствие лишних записей и повторов,
  retry загрузки и остановку после detach. Тест событий проверяет порядок keyup
  и повторного keydown, независимость modal и снятие listeners/callbacks.
  `npm run verify` проходит; браузерный проход остаётся отдельной проверкой.

## 4. Жесты и доступность

- Ревью: отмена жеста не учитывала потерю pointer capture, правую кнопку мыши
  и отсутствие compatibility click; диалог не имел accessible name и
  намеренного начального фокуса. Закрытие ошибки загрузки убирало retry.
- Исправление: жест имеет одну origin и идентификатор подавляемого click;
  cancel/lostcapture не начисляет очков, новый tap и клавиатура не блокируются.
  На карточке разрешён pinch zoom. Диалоги именуются через `aria-labelledby`,
  фокусируются на заголовке, отмене подтверждения или первом угадывающем.
  Ошибка загрузки остаётся доступной для retry; готовность офлайн показана в
  правилах, сбой регистрации worker виден в интерфейсе.
- Проверка: четыре сценария жестов (оба направления, cancellation, чужой
  pointer, короткий/диагональный жест, правая кнопка, click suppression и
  клавиатура); `npm run verify` проходит — 46 тестов. Реальные pointer/focus/SW
  взаимодействия будут проверены итоговым браузерным проходом.

## 5. Типы, движок и компоненты

- Ревью: проверка `noUncheckedIndexedAccess` выявила 21 недоказанное обращение
  к массивам. Правила начисления читались как цепочка вложенных ternary;
  форматирование счёта/журнала жило в движке/разметке; App содержал целиком
  экран передачи телефона и правила, а контроллер назывался `c`.
- Исправление: включены проверки индексов, возвратов, switch и неиспользуемого
  кода. Доступ к игрокам и непустой рейтинг имеют явные контракты; убраны
  assertions слова/фазы, switch проверяет исчерпываемость. Начисление очков
  читается отдельными ветками и сохраняет ссылки на неизменённых игроков.
  Нулевой тик не создаёт новое состояние. Представление вынесено в небольшой
  модуль; Ready/Rules стали компонентами; используются ясные имена/derived
  значения. CSS сгруппирован, удалён мёртвый selector и временный хвост правки.
- Проверка: `npm run verify` — 50 тестов, ноль диагностик. Добавлена полная
  детерминированная партия через все фазы с сериализацией каждого состояния,
  замороженными входами reducer и проверкой отсутствия повторов; ошибочный
  источник shuffle отвергается до повреждения колоды.

## 6. Постоянные проверки качества

- Ревью: форматтер и компилятор не проверяли небезопасный `any`, обработку
  Promise, Svelte-специфичные ошибки и идентичность элементов each.
- Исправление: официальный `eslint-plugin-svelte`, typed recommended
  `typescript-eslint`, flat config и совместимость с Prettier. Runes-модули
  парсятся как TypeScript по конфигурации Svelte. Код имеет явные блоки условий,
  списки — ключи (редактируемые имена хранятся по позиции, не по меняющемуся
  тексту). Исправлены contextual types mocks. Зависимости зафиксированы lockfile.
  `npm run verify` и CI теперь включают lint с нулём предупреждений.
- Проверка: typed lint проходит без blanket suppression; format, типы,
  50 тестов и production-сборка проходят. npm audit при установке: 0 уязвимостей.

## 7. Браузерное контрсвидетельство: фокус

- Production-проверка обнаружила выход фокуса в BODY/браузер при Shift+Tab на
  первой кнопке native dialog. Это не покрывалось доменными тестами.
- Исправление: диалог явно замыкает Tab/Shift+Tab на своих доступных действиях;
  остальные клавиши и Escape остаются нативными.
- Повторная проверка на новой production-сборке: Shift+Tab с «Закрыть» переходит
  к последней ссылке, Tab с ссылки — к «Закрыть»; оба фокуса внутри dialog.
  Escape возвращает фокус к «Правила». Обновление SW сохранило текущую партию
  и слово; применённый asset проверен по DOM. `npm run verify` проходит.

## 8. Повторное ревью настройки и браузерных ошибок

- Браузерный проход выявил дублирование автоматически добавленного имени после
  удаления/переименования игрока. Повторное ревью обнаружило изменение настроек
  до успешного создания новой партии и общий массив настроек с игровой моделью.
- Исправление: добавление/удаление игрока принадлежит контроллеру и соблюдает
  общие ограничения; автоматически выбранное имя свободно. Новая партия
  сначала полностью создаётся, затем применяется; редактируемые массивы
  отделены от её конфигурации. UI, сохранение и WebMCP используют общие пределы.
  Ошибки установки/обновления PWA имеют recovery в интерфейсе.
- Проверка: три регрессии; `npm run verify` проходит — 53 теста, ноль диагностик
  Svelte/TypeScript и предупреждений ESLint, корректный формат и production build.
  Development-браузер не сообщает ошибок/warnings, включая 12 игроков и имена
  длиной 24 символа на экране 320 × 568.

## Итоговый браузерный проход

- Production: одиночное нажатие на игрока даёт +1 ему и +0,5 объясняющему;
  свайп вниз даёт −1 объясняющему, включая отрицательный счёт. Свайп вверх
  открывает выбор игрока; compatibility click не вызывает повторное действие.
  Обычный tap после свайпа остаётся рабочим.
- Открытый выбор игрока сохраняет точное время, ручная пауза скрывает слово.
  Две отмены возвращают исходное слово, счёт и размер оставшейся колоды.
  После естественного истечения таймера текущее слово доигрывается без времени;
  результат хода и передача следующему объясняющему корректны.
- Проверены 320 × 568, 390 × 844, 768 × 1024, 1280 × 800 и 844 × 390:
  нет горизонтального переполнения и обрезанных кнопок; время на паузе неизменно.
  Дополнительно проверены 12 игроков с длинным именем в development-сборке.
- Обновление service worker применено кнопкой на production-сборке;
  новая версия подтверждена по загруженному JS asset. Партия сохранена.
  После остановки preview-сервера страница перезагружена из кэша, сохранённая
  партия продолжена с прежним словом «античность», игроками, счётом и временем.
  Production-консоль не содержит ошибок или предупреждений.
- Установка и жесты на физических iOS/Android-устройствах не проверялись.
  Браузерный проход дополняет автоматические проверки; он не доказывает
  отсутствие всех возможных ошибок.
