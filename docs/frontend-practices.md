# Frontend practices for Alias Local

Research date: 2026-10-07. Scope: the existing Svelte 5 / TypeScript application, its turn clock, local saves, dialogs, gestures and generated service worker. File observations below describe the source inspected during research; implementation may subsequently change. Browser contracts come from primary documentation and specifications. Recommendations that combine those contracts with this game's rules are explicitly application-level conclusions.

## Keep the current Svelte and domain split

- Keep `game.ts` as a synchronous domain reducer and `controller.svelte.ts` as the owner of browser effects. Replacing whole game objects fits `$state.raw`: Svelte documents reassignment, rather than nested mutation, for this rune. The large dictionary object also fits raw state; editable setup configuration can remain deeply reactive. Application-level conclusion: do not add stores or another state framework just to reorganize the same state. [Svelte `$state.raw`](https://svelte.dev/docs/svelte/$state#$state.raw)
- Keep display values such as `paused`, `lastWord` and seconds in `$derived`; move repeated explainer/eligible-player expressions into named derived values when that makes the template clearer. Keep dispatches in named event handlers rather than effects. Plain variables are appropriate for gesture coordinates that never render. Prefer keyed player loops with stable `player.id`, including the picker loop. These follow Svelte's documented rules for state, derivations, events and keyed lists. [Svelte best practices](https://svelte.dev/docs/svelte/best-practices)
- Preserve the discriminated `Action` union and explicit switch branches; an exhaustive `never` check can make a future unhandled action a compile-time error. Application-level conclusion: keep score arithmetic in integer half-point units, inject randomness and time for deterministic domain verification, and leave storage and DOM events outside the reducer. The existing pure transition tests are useful evidence for this boundary. [TypeScript discriminated unions and exhaustiveness](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#exhaustiveness-checking), [Svelte raw-state reassignment](https://svelte.dev/docs/svelte/$state#$state.raw)
- Keep the synchronous `onMount` callback returning cleanup in `App.svelte`; an `async` callback returns a promise rather than Svelte's cleanup function. Cleanup must also release interaction state and any queued callbacks owned by the controller, not just its interval and listeners. Application-level conclusion: a disposed controller must not keep accounting time. [Svelte lifecycle hooks](https://svelte.dev/docs/svelte/lifecycle-hooks#onMount)

## Decode saved JSON at a real runtime boundary

`decodeGame` currently reads properties from the `JSON.parse` result and casts game data before checking it. The legacy branch maps arrays before validating their shape. `loadDictionaries` similarly asserts the response type before examining the root.

- Give parsed data the type `unknown`, check for a non-null non-array object, then inspect the version envelope, nested game and arrays. Narrow fields before accessing, comparing or mapping them; only return `GameState` after validation. A type assertion does not add runtime checking. Small concrete guards are enough for these two formats; a schema dependency is an implementation choice, not a prerequisite. [TypeScript assertions](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#type-assertions)
- Align the accepted state with `createGame`: names must be trimmed, nonempty and unique; selected packs must be known and nonempty; player names should correspond to configuration names. Validate legacy players/logs before conversion, then run the current validator. Apply the existing word constraints consistently to logs. Preserve negative integer score units and legacy entries with no explainer bonus, which are valid here. Application-level conclusion: reject impossible combinations such as a resumable playing phase without a word or positive remaining time, rather than letting `game.word!` hide corrupted input. [TypeScript type predicates](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#using-type-predicates), [TypeScript assertions](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#type-assertions)
- Keep storage failure recoverable and visible. Accessing `localStorage` can throw `SecurityError`; writes can throw `QuotaExceededError`. The controller currently obtains `localStorage` before `loadLocal` enters its catch, so include storage acquisition in the recovery boundary too. Only report a save as successful after the relevant writes finish. Application-level conclusion: separate preference and game reads so a damaged preference record need not hide a usable game. [HTML Web Storage](https://html.spec.whatwg.org/multipage/webstorage.html#the-localstorage-attribute)

## Make gestures cancellable and single-action

- In `Play.svelte`, end a gesture on matching `pointerup`, `pointercancel`, lost capture, backgrounding and teardown. Cancellation clears coordinates without guessing or skipping; do not let capture loss after a successful swipe erase pending click suppression. Use one active pointer identity and an explicit primary-button policy. `isPrimary` identifies a pointer, not the left mouse button. [Pointer Events: buttons, cancellation and capture](https://www.w3.org/TR/pointerevents3/)
- Keep swipe action on release. Associate suppression with the completed gesture, then consume its generated click without swallowing a later ordinary tap. `preventDefault()` on a pointer event does not prevent `click`; explicit suppression is required. Keep native button clicks for keyboard and assistive activation. The existing `swiped` flag addresses this problem but needs cancellation and missing-click coverage. [Pointer Events: click behavior](https://www.w3.org/TR/pointerevents3/#compatibility-mapping-with-mouse-events), [WCAG pointer cancellation](https://www.w3.org/TR/WCAG22/#pointer-cancellation)
- Restrict touch policy to the word card. For vertical custom swipes, consider `touch-action: pan-x pinch-zoom` so the browser can retain horizontal panning and zooming. Verify the actual scroll containers on phones; do not disable gestures across the page. The browser determines allowed direct manipulation from the target and ancestors before the gesture begins. [Pointer Events: touch-action](https://www.w3.org/TR/pointerevents3/#the-touch-action-css-property)

## Clock holds must follow actual interaction lifetimes

Keep elapsed accounting from monotonic `performance.now()` differences; the 100 ms interval is a wake-up mechanism, not a guaranteed amount of elapsed time. Maintain an injected clock for tests. [High Resolution Time: monotonic clock](https://w3c.github.io/hr-time/#sec-monotonic-clock)

Application-level conclusion: keep independently owned holds for pointers, keyboard activation, the picker and app dialogs. Release one reason without releasing the others; clear physical-input holds on cancellation or loss of focus. Acquire a dialog hold before showing it and release it only on close or teardown. In the inspected code, `pauseForBackground()` calls `clock.clear()` while `App.svelte` may still have a modal open: preserve/reacquire that modal hold, or close the modal as part of background handling, so a resumed clock cannot run behind it. Verify Enter and Space activation, repeat keydown and missed keyup; a zero-delay callback alone is not an interaction ownership model. [UI Events: keyboard event order](https://www.w3.org/TR/uievents/#events-keyboard-event-order), [HTML modal-dialog behavior](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)

## Persist on lifecycle transitions and before reload

Keep saving after domain actions and when the document becomes hidden. Hidden is often the last observable state on mobile; `pagehide` can supplement it, but unload-time handlers cannot guarantee a final save. Pause the game and reset the clock anchor when hiding, keep it paused after returning, and save preferences as part of that boundary. Avoid relying on component teardown for mobile process termination. [Chrome Page Lifecycle guidance](https://developer.chrome.com/docs/web-platform/page-lifecycle-api#developer-recommendations-for-each-state)

Application-level conclusion: the update button must check the success returned by `pauseForBackground()` before `updateServiceWorker(true)`. A failed save should retain the current page and show the existing recoverable error. Reloading anyway discards the in-memory game. Preserve the prompt update strategy so an update cannot interrupt a turn without an explicit user action. [Vite PWA Svelte update API](https://vite-pwa-org.netlify.app/frameworks/svelte), [Vite PWA prompt strategy](https://vite-pwa-org.netlify.app/guide/prompt-for-update.html), [HTML storage write errors](https://html.spec.whatwg.org/multipage/webstorage.html#dom-storage-setitem)

## Accessible dialogs need names and intentional focus

Keep native `<dialog>` and `showModal()` for modal/inert behavior. Add a stable heading ID and `aria-labelledby`: the current visible `<h2>` does not automatically give the dialog an accessible name. Give each instance a distinct ID if two dialogs can exist. [HTML dialog](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element), [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

Set an intentional initial focus target: the first eligible player in the picker; the cancel/continue action for destructive confirmations; a focusable heading or introductory element for the long rules dialog. Check Tab/Shift+Tab containment, Escape closing, timer-hold release and restoration to a still-present trigger. Prefer one open app dialog at a time. These choices apply the APG focus guidance to this game's content. Keep visible guess and skip buttons as keyboard equivalents of swipes. [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [WCAG keyboard access](https://www.w3.org/TR/WCAG22/#keyboard)

## Verify the shipped offline experience

- Keep dictionaries in the revisioned precache with HTML, scripts, CSS and icons. Confirm the generated `dist/sw.js` includes them and the deployment base path matches their fetch URLs; Workbox installation caches its manifest and activation cleans obsolete entries. File-size exclusions are build-time concerns, so inspect output rather than assuming an `includeAssets` entry guarantees caching. [Workbox precaching](https://developer.chrome.com/docs/workbox/modules/workbox-precaching)
- Use `offlineReady` to distinguish cache readiness from merely having downloaded the page, and `onRegisterError` to expose failed registration through the existing error UI. Preserve the Svelte adapter's stores; its example uses older component syntax, so translate callbacks into the project's Svelte 5 handlers. [Vite PWA Svelte integration](https://vite-pwa-org.netlify.app/frameworks/svelte)
- Exercise the production build: first online visit through worker activation, offline reload, dictionary availability, restoration of an unfinished turn, and update acceptance after a successful save. Add domain tests for malformed JSON and overlapping hold transitions; use a real browser for dialog focus, pointer cancellation and service-worker behavior. These scenarios test the actual boundaries identified above. [Svelte testing guidance](https://svelte.dev/docs/svelte/testing), [Workbox precaching lifecycle](https://developer.chrome.com/docs/workbox/modules/workbox-precaching)
